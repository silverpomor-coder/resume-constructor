# Паспорт проекта: Constructor Resume

## 1. Назначение проекта

Проект — локальный конструктор корпоративного резюме для агентства.

Основной сценарий:

1. Пользователь открывает локальное приложение в браузере.
2. Загружает исходное резюме кандидата.
3. Выбирает режим распознавания: `Авто` или `HH`.
4. Приложение извлекает данные из файла.
5. Данные появляются в форме редактирования.
6. Пользователь вручную проверяет и исправляет поля.
7. Приложение сохраняет итоговое резюме в корпоративный DOCX-шаблон.
8. Пользователь может открыть папку, куда сохранен готовый файл.

Цель проекта — привести разные источники резюме к единой структуре данных и быстро получить резюме на корпоративном бланке.

## 2. Текущий стек

- Язык: Python.
- Веб-сервер: Flask.
- Интерфейс: HTML, CSS, JavaScript без сборщика и без frontend-фреймворков.
- Формат итогового документа: DOCX.
- Работа с DOCX: через стандартные Python-библиотеки `zipfile` и `xml.etree.ElementTree`.
- Зависимости проекта:
  - `Flask`;
  - `pyinstaller` для будущей упаковки в Windows-приложение.

Файл зависимостей: `requirements.txt`.

## 3. Главные файлы проекта

- `app.py` — основная серверная логика Flask-приложения.
- `templates/index.html` — основной HTML-интерфейс.
- `static/app.js` — клиентская логика загрузки, переключения режима, редактирования, сохранения.
- `static/styles.css` — стили интерфейса.
- `CV_sample_v2.docx` — корпоративный DOCX-шаблон.
- `desktop_launcher.py` — локальный запуск приложения с автоматическим открытием браузера.
- `requirements.txt` — Python-зависимости.
- `GENPLAN.md` — общий план развития проекта.
- `app_settings.json` — локальные настройки, создаются/обновляются приложением, сейчас используются для запоминания последней папки сохранения.
- `WIN_relise/` — подготовленная папка для переноса минимального рабочего комплекта на Windows.

Рабочие папки:

- `Start/` — исходные и тестовые файлы.
- `uploads/` — временные копии загруженных файлов.
- `готовые резюме/` — папка по умолчанию для готовых резюме.

## 4. Текущий интерфейс

Интерфейс состоит из верхней панели и трех рабочих колонок.

Верхняя панель:

- название приложения;
- строка статуса;
- кнопка `Авто`;
- кнопка `HH`;
- кнопка `Загрузить`;
- кнопка `Сохранить`;
- кнопка `Открыть`.

Рабочие колонки:

1. `Исходный текст` — показывает текст, извлеченный из загруженного файла.
2. `Финальный документ` — показывает предпросмотр данных, которые попадут в итоговое резюме.
3. `Редактирование` — форма с полями для ручной корректировки.

Колонки можно менять по ширине через разделители.

Фон рабочей области за панелями: `#11b2d0`.
Сами панели остаются белыми для читаемости.

## 5. Поддерживаемые форматы входных файлов

Приложение принимает:

- `.doc`;
- `.docx`;
- `.rtf`;
- `.txt`;
- `.odt`.

Особенность:

- на macOS старые `.doc` могут читаться через системный `textutil`;
- на Windows чтение старых `.doc` может быть менее надежным;
- `.docx`, `.rtf`, `.txt`, `.odt` являются более предпочтительными форматами.

## 6. Единая структура данных

Все режимы распознавания возвращают один набор полей.

Основные поля:

- должность / желаемая роль;
- ожидаемый размер оплаты;
- ФИО;
- телефон;
- электронная почта;
- гражданство;
- место и дата рождения;
- семейное положение / дети;
- регистрация;
- фактическое местонахождение;
- метро / станция электрички;
- судимость;
- языки;
- медицинская книжка;
- водительские права;
- кандидат о себе;
- комментарий агентства;
- образование;
- учебное заведение;
- курсы;
- предыдущая занятость;
- рекомендации.

Блок занятости динамический: количество рабочих мест определяется по распознанным данным.

## 7. Режимы распознавания

### Авто

Режим `Авто` использует текущую универсальную функцию `parse_resume(text)`.

Он предназначен для:

- старых успешных форматов;
- агентских анкет;
- нестандартных резюме с ручной доводкой.

В `Авто` также добавлена поддержка ФИО из двух слов перед строкой пола кандидата, например `Муратова Светлана`.

### HH

Режим `HH` использует отдельную функцию `parse_hh_resume(text)`.

Режим сделан специально под выгрузки HeadHunter.

Текущие правила HH:

- ФИО берется из первой непустой строки перед строкой `Женщина/Мужчина, ...`.
- Зарплата берется после блока `Желаемая должность и зарплата` из строки с `₽`, `руб` или `на руки`.
- Город и метро берутся из строки `Проживает: ...`.
- Пример: `Проживает: Москва, м. Внуково`:
  - `location = Москва`;
  - `metro = Внуково`.
- Опыт работы начинается после строки `Опыт работы...`.
- Опыт работы заканчивается только на точной строке `Образование`.
- Фразы вроде `Образование и воспитание детей...` не обрывают опыт.
- Места работы делятся по строкам периода, например:
  - `Август 2024 — настоящее время`;
  - `Сентябрь 2005 — Май 2006`.
- Следующая строка после периода, если это длительность, добавляется к периоду.
- Образование берется из блока `Образование` до точной строки `Навыки` или `Повышение квалификации, курсы`.
- Языки берутся из блока `Знание языков`.
- Права берутся из блока `Опыт вождения`.
- `Обо мне` берется из блока `Обо мне` в дополнительной информации.

## 9. Сохранение итогового DOCX

Текущая логика сохранения:

1. Пользователь нажимает `Сохранить`.
2. Сервер формирует временный DOCX.
3. Открывается системное окно выбора места сохранения.
4. Пользователь подтверждает место или выбирает другую папку.
5. Файл сохраняется по выбранному пути.
6. Папка сохранения запоминается в `app_settings.json`.
7. При следующем сохранении окно открывается в последней выбранной папке.
8. Кнопка `Открыть` открывает папку, где лежит последний сохраненный файл.

На macOS для окна сохранения используется `osascript`, потому что `tkinter` может аварийно завершать Python при вызове из Flask-запроса.

Для Windows предусмотрен fallback через `tkinter.filedialog`.

Обычный запуск:

```bash
python3 app.py
```

Адрес приложения:

```text
http://127.0.0.1:5000
```

Для запуска с автоматическим открытием браузера используется:

python3 desktop_launcher.py

- `install_windows.bat` — установка зависимостей;

В нее помещен минимальный комплект:

Не включены:

- `.DS_Store`;

1. Установить Python 3.11 или 3.12.
2. Открыть папку `WIN_relise`.
3. Один раз запустить `install_windows.bat`.
4. Для работы запускать `start_windows.bat`.

## 12. Текущая архитектура

Приложение сейчас является локальным монолитом.

Схема:

```text
Браузер пользователя
        |
        | HTTP localhost
        v
Flask-приложение app.py
        |
        | читает входной файл
        v
normalize_to_text()
        |
        | передает текст
        v
parse_resume() или parse_hh_resume()
        |
        | возвращает единую структуру данных
        v
HTML/JS форма редактирования
        |
        | отправляет JSON на /save
        v
fill_template()
        |
        | заполняет CV_sample_v2.docx
        v
итоговый DOCX
```

Основные HTTP-маршруты:

- `GET /` — основной интерфейс;
- `POST /upload` — загрузка и распознавание файла;
- `POST /save` — формирование и сохранение DOCX;
- `POST /open-output-folder` — открыть папку сохраненного файла;
- `GET /download/<session_id>` — скачивание файла, исторически оставлено;
- `GET /health` — проверка работоспособности.

Сессии хранятся в памяти процесса в словаре `SESSIONS`.

Это нормально для локального приложения, но для облака нужно заменить на более устойчивое хранение.

## 13. Ограничения текущей локальной версии

- Сессии теряются при перезапуске приложения.
- `uploads/` может накапливать временные файлы.
- Старые `.doc` зависят от возможностей ОС.
- Сохранение через системное окно подходит для локальной версии, но не подходит для облачной.
- Одновременная работа нескольких пользователей не является текущей целевой моделью.

## 14. Возможность развертывания в Yandex Cloud

Развернуть проект в Yandex Cloud возможно, но не в текущем виде один в один.

Главный вывод:

- `Object Storage` сам по себе не запустит Python-приложение.
- Для запуска нужен вычислительный сервис.
- `Object Storage` полезен как хранилище файлов.

Из инфраструктуры Yandex Cloud подходит:

### Compute Cloud

Основной вариант для MVP.

На виртуальной машине запускается Flask-приложение.

Пользователь работает через браузер по ссылке.

Плюсы:

- проще всего перенести текущую архитектуру;
- можно быстро поднять рабочую версию;
- минимум переделок.

Минусы:

- нужно администрировать виртуальную машину;
- нужно настроить безопасность, домен, HTTPS, резервные копии.

### Object Storage

Использовать для хранения:

- исходных загруженных резюме;
- готовых DOCX;
- шаблона DOCX;
- резервных копий.

Не использовать как место запуска приложения.

### Cloud DNS

Нужен только если будет домен, например:

```text
resume.company.ru
```

### Application Load Balancer

На MVP не нужен.

Может понадобиться позже для:

- HTTPS;
- домена;
- масштабирования;
- нескольких серверов.

## 15. Что нужно изменить для облачной версии

Для Yandex Cloud нельзя оставлять текущую модель сохранения через системное окно.

Причина:

- Python будет работать на сервере;
- системное окно откроется на сервере, а не у пользователя.

Правильная облачная логика:

1. Пользователь нажимает `Сохранить`.
2. Сервер формирует DOCX.
3. Файл сохраняется в Object Storage или во временное хранилище.
4. Браузер пользователя получает ссылку на скачивание.
5. Пользователь скачивает DOCX через браузер.

Для облака нужно заменить:

- локальное окно выбора файла;
- локальную кнопку `Открыть папку`;
- хранение сессий только в памяти;
- локальные пути `uploads/` и `готовые резюме/`.

Рекомендуемая облачная архитектура MVP:

```text
Пользовательский браузер
        |
        v
Compute Cloud VM с Flask-приложением
        |
        +--> Object Storage: исходные файлы
        |
        +--> Object Storage: готовые DOCX
        |
        +--> временная память/диск: обработка файла
```

## 16. Что должно остаться локально у пользователя в облачной версии

Если приложение будет развернуто в Yandex Cloud, на устройстве пользователя нужно только:

- браузер;
- ссылка на приложение;
- возможно ярлык на рабочем столе.

Python, проектные файлы и шаблоны на локальном устройстве не нужны.

## 17. Рекомендация по дальнейшему развитию

Ближайшие технические шаги:

1. Зафиксировать текущую локальную версию как стабильную.
2. Отдельно сделать ветку/режим `cloud`.
3. В cloud-режиме заменить сохранение через системное окно на скачивание файла.
4. Перенести хранение файлов в Object Storage.
5. Поднять приложение на Yandex Compute Cloud.
6. Проверить работу с несколькими пользователями.
7. После этого решать вопрос с доменом, HTTPS и авторизацией.

## 18. Краткое резюме для ChatGPT

Это Flask-приложение для локального распознавания резюме и генерации корпоративного DOCX.

Сейчас оно работает как локальный веб-интерфейс:

- пользователь открывает `localhost`;
- загружает резюме;
- выбирает `Авто` или `HH`;
- редактирует распознанные поля;
- сохраняет DOCX через системное окно выбора места.

Главные реализованные доработки:

- отдельный HH-парсер;
- переключатель `Авто / HH`;
- автоматическое повторное распознавание при смене режима;
- динамические поля занятости;
- сохранение DOCX по выбранному пути;
- запоминание последней папки сохранения;
- кнопка открытия папки результата;
- минимальный Windows-релиз в папке `WIN_relise`.

Для Yandex Cloud текущую локальную версию нужно адаптировать:

- запускать Flask на Compute Cloud;
- файлы хранить в Object Storage;
- вместо локального окна сохранения отдавать DOCX браузеру на скачивание;
- локальному пользователю оставить только браузер и ссылку.

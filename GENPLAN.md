# GENPLAN

## Общая цель

Проект развивается как конструктор корпоративного резюме на бланке агентства.

Есть два основных сценария:

1. Локальный конструктор для сотрудников агентства.
2. Публичная ручная анкета для кандидатов на сайте Tilda.

Все источники данных должны приводиться к одной структуре полей, после чего сохраняться в итоговое резюме на корпоративном шаблоне.

## 1. Локальный конструктор

Текущий локальный конструктор сохраняем как основную рабочую часть.

Сценарий:

1. Загрузить исходное резюме.
2. Распознать данные.
3. Показать данные в правой колонке.
4. Отредактировать вручную.
5. Сохранить готовое резюме в корпоративный DOCX.

Основные правила распознавания настраиваем под два главных формата:

- резюме с HeadHunter;
- анкета, заполненная вручную в агентстве.

Редкие и нестандартные резюме добавляются позже отдельными правилами.

## 2. Единая структура данных

Правая колонка становится главным редактором данных.

Неважно, откуда пришли данные:

- из загруженного резюме;
- из агентской анкеты;
- из публичной формы на сайте.

На выходе всегда должен быть один набор полей:

- ФИО;
- контакты;
- персональные данные;
- образование;
- предыдущая занятость;
- рекомендации;
- комментарии;
- прочие поля корпоративного шаблона.

## 3. Публичная анкета на Tilda

Нужно сделать отдельный режим: только форма ручного заполнения.

В этом режиме нет:

- загрузки исходного файла;
- левой колонки с исходным текстом;
- предпросмотра;
- админских функций.

Форма размещается на сайте Tilda через блок T123.

Сценарий кандидата:

1. Кандидат открывает публичную ссылку.
2. Заполняет анкету.
3. Нажимает "Сохранить" или "Отправить".
4. Данные уходят в агентство.

## 4. Прием анкет с сайта

Tilda сама по себе не должна напрямую сохранять файлы в локальную папку агентства.

Нужен небольшой серверный приемщик.

Он должен:

- принимать данные формы;
- проверять простой ключ или защищенную ссылку;
- сохранять анкету в папку "Входящие анкеты".

После этого сотрудник агентства открывает анкету в локальном приложении, проверяет, редактирует и сохраняет итоговое резюме в папку "готовые резюме".

## 5. Доступ кандидата

Для MVP не делать сложную регистрацию.

Использовать один из простых вариантов:

- защищенная ссылка;
- одноразовый ключ;
- скрытый служебный параметр формы.

Админ-панель на первом этапе не нужна.

## 6. Проверка

Обязательные проверки:

- распознавание HeadHunter-резюме;
- распознавание агентской анкеты;
- ручное заполнение формы на Tilda;
- получение анкеты во входящей папке;
- открытие анкеты в локальном приложении;
- сохранение итогового DOCX на корпоративном шаблоне.
